## Context

We need a token system that:

1. Is machine-readable (consultable by AI agents and MCP servers)
2. Generates CSS custom properties for runtime use
3. Supports dark mode without JS
4. Prevents raw hex/px values in component code

## Decision

**Three-layer DTCG JSON → CSS → TypeScript:**

```
primitive.*   → raw scale            (brand.600 = #2563eb)
semantic.*    → role aliases         (color.fill.primary = {primitive.color.brand.600})
component.*   → component aliases    (button.fill.rest = {semantic.color.fill.primary})
```

Source: `packages/tokens/src/tokens.json` (DTCG format)  
Output: `packages/tokens/dist/helix.css` + `packages/tokens/dist/index.ts`

CSS naming: `--helix-{path-with-dashes}` (semantic and primitive prefixes stripped)
- `semantic.color.fill.primary` → `--helix-color-fill-primary`

**Rule:** Component CSS references only semantic tokens. Never primitive tokens directly.

**Dark mode:** the token file defines semantic overrides under `[data-theme="dark"]` AND
`@media (prefers-color-scheme: dark)` to handle both explicit toggle and OS default.

## Consequences

**Positive**
- Adding a dark mode value is a one-line change in `tokens.json`.
- `--helix-color-fill-primary` can point to different primitives in different themes.
- AI agents can look up token values via the JSON file or a future MCP server.

**Negative**
- Adding a new token requires a build step (`pnpm build` in `@helix-ds/tokens`).
- The three layers add indirection — reading component CSS won't show raw values.

**Mitigations**
- The tokens MCP server (Layer 8) exposes resolved values for agent lookup.
- `scripts/verify-contract.ts` and `scripts/prop-map-check.ts` run in CI to catch violations.

## Contracts affected

All component contracts — every component's token references must follow the
primitive → semantic → component aliasing chain defined here.
